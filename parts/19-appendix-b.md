# 附录 B　可以直接拿去用的清单

## B.1 一页规格模板

```
# 规格：<功能名>
版本：<v0.1>   作者：<>   日期：<>

1. 问题陈述
   谁在什么场景下遇到什么问题？不做会怎样？

2. 成功指标
   做完之后，用什么数字判断它成了？（可测量）

3. 用户故事
   作为 <角色>，我希望 <做某件事>，以便 <得到某个结果>。

4. 验收标准（**必须可机械判定**）
   - [ ] 条件 → 预期结果
   - [ ] 条件 → 预期结果
   - [ ] 异常/空/边界情况 → 预期结果

5. 非目标（**最常被忽略，最重要**）
   - 本次不做：<...>   理由：<...>
   - 本次不做：<...>   理由：<...>

6. 约束
   技术限制、合规要求、性能底线、不允许引入的依赖
```

**自查两问**：① 换一个技术栈实现，这份规格还成立吗？② 有一个"非目标"是空的吗？——**空的话，先别开工。**

## B.2 智能体协作说明骨架（约 100 行以内）

```
# <项目名> — 协作说明

## 1. 项目概览
一段话说明这是什么、为谁做。

## 2. 常用命令
安装 / 构建 / 测试 / 静态检查 / 启动本地环境

## 3. 目录约定
哪个目录放什么。**这一节是索引，不是百科**——细节请指向深层文档。

## 4. 变更纪律
- 一次变更只做一件事
- 不改动与本次任务无关的代码
- 变更大小以"人能一次审完"为上限

## 5. 测试纪律
- 改动必须带测试
- 发布前禁用模拟对象
- 连续失败到约定的次数 → 停止，转人工（这个次数必须写死，不能"看情况"）

## 6. 安全红线（不可协商）
- 不得执行删除、对外请求、资金、权限变更、生产发布
- 不得把密钥写入代码或上下文
- 新依赖必须人工确认

## 7. 遇到不确定时
**先问，不许猜。**把不确定的地方列出来，等确认。

## 8. 需要人工确认的动作
<逐条列出>
```

## B.3 门禁清单（可直接落到持续集成）

| # | 门禁 | 拦什么 | 例外条件 | **废止条件** |
|---|---|---|---|---|
| 1 | 编译 / 类型检查通过 | 语法、类型错误 | 无 | 无 |
| 2 | 静态扫描零新增告警 | 明显的坏味道与常见缺陷 | 记录在案的例外清单 | 规则误报率持续过高 |
| 3 | 单元测试全通过 | 行为不符合预期 | 无 | 无 |
| 4 | **覆盖率不下降**（棘轮） | 新代码绕过安全网 | 无 | 阈值长期无人维护时 |
| 5 | 新增代码重复率不上升 | 复制粘贴堆积 | 无 | 检测误报率高时 |
| 6 | 依赖来源白名单 | 幻觉依赖、包名蹭用 | 经人工确认的新依赖 | 无 |
| 7 | 密钥扫描无命中 | 凭据泄露 | 无 | 无 |
| 8 | 变更大小超阈值 → 需人工确认 | 无法审完的巨型变更 | 明确的机械性变更 | 若长期无此类变更 |

> **给每一条门禁写"废止条件"**——这一栏几乎没有团队会写，而它恰好最有用：**一个不会过期的阈值，迟早变成摆设。**

## B.4 智能体安全配置清单

- [ ] 每个智能体**唯一的服务账号**（不共用凭据）
- [ ] **任务级短时凭据**，任务结束自动失效
- [ ] 隔离执行环境：**文件系统与网络同时隔离**（只做文件隔离不够）
- [ ] 包管理器指向**内部仓库** + 锁文件校验
- [ ] 密钥**绝不进入上下文**，走代理式调用
- [ ] **六类动作强制人工确认**：删除 / 对外请求 / 资金 / 权限变更 / 生产发布 / 需求与架构变更
- [ ] **行为日志**：提示、检索内容、工具调用、执行动作全部留痕
- [ ] **AI 物料清单**：记录模型版本、提示版本、依赖清单；扫描通过并人工签名后方可合并
- [ ] 破坏性动作先在**一次性环境**演练
- [ ] 定期做**权限体检**：找出"它其实不需要"的权限并删掉

## B.5 指标定义表（模板）

| 层 | 指标 | 定义（分子 / 分母） | 反向指标 | 谁负责 |
|---|---|---|---|---|
| 使用 | 活跃用户数 | — | 沉默 / 流失用户占比 | 工具负责人 |
| 使用 | 采纳率 | **必须写清是四层里的哪一层** | 入库率 | 工具负责人 |
| 过程 | 首次评审等待时长（P90） | 提交到首次评审的时间 | 缺陷逃逸率 | 研发负责人 |
| 过程 | 变更平均大小 | 变更行数 / 变更数 | 返工量 | 团队负责人 |
| **结果** | **入库率** | **真实合入主干的有效代码量 ÷ 应交付代码量** | 返工量 | 研发负责人 |
| **结果** | **端到端交付周期** | 需求确认 → 上线 | 缺陷逃逸率 | 研发负责人 |
| **结果** | **缺陷逃逸率** | 生产发现的缺陷 ÷ 总缺陷 | 交付周期 | 质量负责人 |

> **三条纪律**：① **只对外承诺"结果"层**；② **每个指标必须配一个反向指标**；③ **目标值与达成值分列，不得并进同一格。**
