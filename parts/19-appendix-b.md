# 附录 B　可以直接拿去用的清单

## B.1 一页规格模板

```
# 规格：<功能名>
版本：<v0.1>   作者：<>   日期：<>

1. 问题陈述
   谁在什么场景下遇到什么问题？不做会怎样？

2. 成功指标
   做完之后，用什么数字判断它成了？（可测量）

3. 用户故事
   作为 <角色>，我希望 <做某件事>，以便 <得到某个结果>。

4. 验收标准（**必须可复核，能自动化的尽量自动化**）
   - [ ] 条件 → 预期结果；验证命令或检查方法：<>
   - [ ] 异常/空/边界情况 → 预期结果；验证方法：<>
   - [ ] 人工验收项：<>；责任人：<>；方法：<>；通过条件：<>

5. 非目标（**最常被忽略，最重要**）
   - 本次不做：<...>   理由：<...>
   - 本次不做：<...>   理由：<...>

6. 约束
   技术限制及理由、合规要求、性能底线、不允许引入的依赖
```

**自查三问**：① 能独立验证、由负责的人一次审完吗？② 明确的技术约束与可替换的实现选择区分开了吗？③ "非目标"写清楚了吗？——**边界没想清楚，先别开工。**换栈检验只能辅助区分需求与实现，不能判断粒度；规格从一页写起，长度随歧义和风险调整。

## B.2 智能体协作说明骨架（约 100 行以内）

```
# <项目名> — 协作说明

## 1. 项目概览
一段话说明这是什么、为谁做。

## 2. 常用命令
安装 / 构建 / 测试 / 静态检查 / 启动本地环境

## 3. 目录约定
哪个目录放什么。**这一节是索引，不是百科**——细节请指向深层文档。

## 4. 变更纪律
- 一次变更只做一件事
- 不改动与本次任务无关的代码
- 变更大小以"人能一次审完"为上限

## 5. 测试纪律
- 改动必须带测试
- 发布验收不能只依赖模拟对象：保留可注入超时、权限拒绝、错误响应的模拟测试
- 为关键链路补真实依赖集成验证，核对模拟中的假设；使用经授权的隔离环境与代表性数据，不直接使用生产原始数据
- 连续失败到约定的次数 → 停止，转人工（这个次数必须写死，不能"看情况"）

## 6. 安全红线（不可协商）
- 未经人工确认，不得执行删除、对外请求、资金、权限变更、生产发布、需求与架构变更
- 不得把密钥写入代码或上下文
- 新依赖的包及版本必须经人工审批、通过受控准入；不得绕过内部仓库获取未知公共包

## 7. 遇到不确定时
**先问，不许猜。**把不确定的地方列出来，等确认。

## 8. 需要人工确认的动作
<逐条列出>
```

## B.3 门禁清单（可直接落到持续集成）

| # | 门禁 | 拦什么 | 例外条件 | **废止条件** |
|---|---|---|---|---|
| 1 | 编译 / 类型检查通过 | 语法、类型错误 | 无 | 无 |
| 2 | 静态扫描零新增告警 | 明显的坏味道与常见缺陷 | 经审批、记录在案的例外清单 | 已有经验证的等效扫描替代 |
| 3 | 单元测试全通过 | 行为不符合预期 | 无 | 无 |
| 4 | **覆盖率不下降**（棘轮） | 新代码绕过安全网 | 无 | 已有经验证的等效测试控制替代 |
| 5 | 新增代码重复率不上升 | 复制粘贴堆积 | 无 | 已有经验证的等效检测替代 |
| 6 | 依赖来源与包版本准入 | 幻觉依赖、包名蹭用、未经审批的版本 | 按准入流程审批的新包及版本 | 无 |
| 7 | 密钥扫描无命中 | 凭据泄露 | 无 | 无 |
| 8 | 变更大小超阈值 → 需人工确认 | 无法审完的巨型变更 | 经人工确认的机械性变更 | 适用范围改变而不再适用，或已有经验证的等效审查控制 |

> **给每一条门禁写"废止条件"**：风险确已消失、适用范围改变而不再适用，或已有经验证的等效控制，才有退役依据。无人维护应补责任人，误报高应修规则，不能因此直接撤销；长期无命中或无大变更也不是理由。**没有违规时，零命中可能恰恰正常；要用正常样例与已知违规样例验证能通过、能阻断。**

## B.4 智能体安全配置清单

- [ ] 每个智能体**唯一的服务账号**（不共用凭据）
- [ ] **任务级短时凭据**，任务结束自动失效
- [ ] 隔离执行环境：**文件系统与网络同时隔离**（只做文件隔离不够）
- [ ] 包管理器仅从**受控内部仓库**取包：只准入**经审批的包及版本**，不得自动透传未知公共包；锁文件用于重复性与完整性校验，**不能代替准入审批**
- [ ] 密钥**绝不进入上下文**，走代理式调用
- [ ] **六类动作强制人工确认**：删除 / 对外请求 / 资金 / 权限变更 / 生产发布 / 需求与架构变更
- [ ] **行为日志**：提示、检索内容、工具调用、执行动作脱敏留痕、受控保存，不记录密钥或未授权数据
- [ ] **AI 物料清单**：记录模型版本、提示版本、依赖清单；扫描通过并人工签名后方可合并
- [ ] 破坏性动作先经人工确认，再在**一次性环境**演练；演练不替代后续实际执行的授权
- [ ] 定期做**权限体检**：找出"它其实不需要"的权限，经人工确认后移除

## B.5 指标定义表（模板）

| 层 | 指标 | 定义（口径 / 分子与分母） | 反向指标 | 谁负责 |
|---|---|---|---|---|
| 使用 | 活跃用户数 | — | 沉默 / 流失用户占比 | 工具负责人 |
| 使用 | 编辑器接受或保留比例（第 14 章正文称"采纳率"） | 限漏斗第 1–2 层；固定观察窗与计量单位，分别定义接受或保留数量 ÷ 生成建议总量，不混算 | 返工比例 | 工具负责人 |
| 过程 | 首次评审等待时长（P90） | 提交到首次评审的时间 | 缺陷逃逸率 | 研发负责人 |
| 过程 | 变更平均大小 | 变更行数 / 变更数 | 返工量 | 团队负责人 |
| **过程** | **合入比例**（第 14 章正文称"入库率"） | 以自然月为观测窗、变更请求为单位：当月首次提交评审的请求中，截至月末已合入主干的数量 ÷ 该批请求总数 | 返工比例 | 研发负责人 |
| **结果** | **端到端交付周期** | 需求确认 → 上线 | 缺陷逃逸率 | 研发负责人 |
| **结果** | **缺陷逃逸率** | 生产发现的缺陷 ÷ 总缺陷 | 交付周期 | 质量负责人 |
| **结果** | **单项交付成本** | 同一交付批次归集的人工与工具成本 ÷ 该批已验收交付事项数 | 缺陷逃逸率 | 研发负责人 |

合入比例中的未合入请求按待审、关闭等状态另列，分母为零时记"不适用"；跨月合入不回填该月快照。它反映的是流转过程，受提交时点影响，**不是价值或质量得分**。代码行数只用于观察变更规模，不用来衡量交付价值；结果仍看**端到端周期、质量与成本**。

> **三条纪律**：① **只对外承诺"结果"层**；② **每个指标必须配一个反向指标**；③ **目标值与达成值分列，不得并进同一格。**
