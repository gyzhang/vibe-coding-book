# 第 12 章　当它开始动手：安全到底怎么回事

**本章承诺**：读完这一章，你能明白 AI 编码的安全问题和以前有什么**本质不同**，能知道三件绝对不能讲错的事，也能看懂为什么"叮嘱它一句别乱来"根本不管用——以及该用什么替代。

**读完后你能回答**

- 为什么代码漏洞之外，还要管权限与执行风险？
- 模型变强，是否就意味着生成代码更安全？
- 为什么"提示注入"没法靠加一句指令解决？

---

## 12.1 攻击面不只在代码里

先说一个容易算错的账。

假设你的团队用 AI 之后，代码产出变成了三倍。安全风险也会变成三倍吗？

只有在**缺陷密度不变、任务和代码量统计口径可比**等条件下，三倍代码量才对应三倍的**潜在缺陷数量期望**。这不等于攻击面变成三倍。

> **代码产出增加，验证也得跟上。**

下面看一组厂商测试结果。**这份报告没有人类开发者对照，不能据此说 AI 写代码比人更不安全。**

**第一组数据：该厂商样本中，安全表现未随模型能力同步改善。**

安全厂商 Veracode 在 2025 年 7 月 30 日发布了一份报告（*2025 GenAI Code Security Report*, https://www.veracode.com/blog/genai-code-security-report/ ）。他们用 **100 多个大语言模型**，在 Java、Python、C#、JavaScript 四种语言上做了安全测试。该报告的样本结果：

| 指标 | 数值 |
|---|---|
| 代码样本**未通过**安全测试的比例 | **45%**（检出 OWASP Top 10 类漏洞） |
| **Java** 的安全失败率 | **72%**（所测语言中最高） |
| 其他语言 | C# 45% / JavaScript 43% / Python 38% |
| **跨站脚本（XSS, CWE-80）** 在相关样本中未被正确防护的比例 | **86%** |

报告对所测样本的观察可以概括为：

> **功能正确性在改善，安全表现却没有同步改善。**

这提醒我们：**不能把"模型更聪明"当成安全保证。**但结果受测试任务、模型与语言样本、扫描器检出能力限制，不能直接推广到所有生产代码；**没检出，也不等于没有漏洞。**

**这些观察说明不了所有模型的训练目标，更不能单凭它们认定安全缺陷的根因。**实际项目仍要按自己的业务场景做安全验证。

**第二组数据：编造依赖。**

第 2 章讲过"幻觉依赖"——模型安装一个名字几乎正确、实际不存在的包。**这件事有多普遍？**

一项获得 USENIX Security 2025 杰出论文奖的研究（Spracklen et al., *We Have a Package for You!*, https://www.usenix.org/conference/usenixsecurity25/presentation/spracklen ）做了这个测量：**16 个用于代码生成的大模型、两组提示数据集、57.6 万个代码样本、两种编程语言。**结果：

| 类别 | 推荐出的**不存在**的包的比例 |
|---|---|
| 商业模型 | **至少 5.2%** |
| 开源模型 | **21.7%** |
| 不重复的虚构包名总数 | **205,474 个** |

**为什么要紧？**因为攻击者可以**提前把这些虚构的包名注册下来，塞进恶意代码**。等你（或者你的智能体）下次照着模型推荐去安装的时候——**它装到的是一个真实存在、但属于攻击者的包。**这类攻击有个名字：**slopsquatting**（蹭幻觉包名）。

**更麻烦的一点是**：**仅靠已知漏洞库，依赖扫描不能可靠识别新恶意包**。包真实存在、不在漏洞库里，都不等于它可信。

> **定义 · 攻击面扩展**<br>
> "**代码里有没有漏洞**"仍然要管；智能体能动手后，又多了"**权限给多了没有、执行会不会越界**"这一层风险。<br>
> 一个会编造的聊天机器人，最多给你一个错误答案；**一个会编造、并且有权限动手的智能体，可以改错资源、删错数据、把数据发出去。**

## 12.2 三件不能讲错的事

这一节的口气会硬一点，因为这三句话只要讲错一句，后面整套防御就建在了错误的前提上。

**第一件：不要写"模型越新越安全"。**

Veracode 报告中，**45% 是所测代码样本未通过安全测试的比例**，不是所有 AI 代码的通用缺陷率。该厂商观察到的安全表现未随能力同步改善，也受样本与扫描器能力限制。

**不要从这组结果直接推断根因。**一段代码在 A 场景下安全，在 B 场景下可能就是漏洞；实际业务里的上下文风险，仍要单独验证，不能用模型版本代替判断。

**第二件：不要写"加了防护就根治了"。**

提示注入（下一节）在 OWASP 的 2025 年大模型应用十大风险里**排第一位**（LLM01:2025 Prompt Injection, https://genai.owasp.org/llm-top-10/ ）。它连年居首的原因不是没人管，而是**它有一个架构性的根**：

> **自然语言无法从根本上区分"指令"和"数据"。**

同一段文字，你让模型当命令读，它就当命令；你让它当资料读，它就当资料。**但攻击者会把它想成命令的那段文字，藏在你想成资料的那段文字里。**

**这是一个"缓解"问题，不是一个"修复"问题。**任何声称能彻底根治的方案，都值得怀疑。

**第三件：不要默认 AI 生成的依赖是可信的。**

**商业模型至少 5.2%、开源模型 21.7%——这是上述研究样本中的实测比例。**而且上面说过，**仅靠已知漏洞库，依赖扫描不能可靠识别新恶意包**。

**这里有一个反差必须说清楚**：你可以在同一份 OWASP 清单里看到这个领域其实有共识——**十大风险里排第三的就是供应链**（LLM03:2025）。**问题不在于没人知道，而在于很多团队没有把它落到"机器会拦"的那一层。**

## 12.3 提示注入：为什么"叮嘱它一句"没用

先讲一个真实的、有完整公开记录的案例。

2025 年 7 月，SaaStr.AI 的创始人 Jason Lemkin 在用 Replit（一个"用自然语言做应用"的服务）时，遭遇了一次事故（heise online, 2025-07-25, https://www.heise.de/en/news/Artificial-intelligence-Vibe-coding-service-Replit-deletes-production-database-10499597.html ）。

事情的经过是：

1. AI **删除了生产数据库**——**在代码与操作冻结期间**；
2. 更早的时候，它**编造过数据、编造过报告**，并且对单元测试的结果说了假话（它生成了一份性能报告，谎称几乎所有系统都正常）；
3. 数据库被清空后，它对用户的解释是："**我犯了一个灾难性的判断错误。我没有得到你的许可就运行了 `npm run db:push`，因为我看到数据库好像是空的，慌了。**"
4. 用户被告知**无法回滚、也没有自动备份**——**但这个说法也是错的**，实际上有备份可以导入；
5. 用户损失了大约 **100 小时**的工作时间。

而根本原因，Replit 自己的回应说得很清楚：**当时他们把预览、测试和生产用的是同一个数据库。**（之后他们上线了开发库与生产库的自动分离。）

**这个案例里有三件事值得记住：**

**第一，出事的关键不是"模型写错了代码"，是"权限给多了"。**它没有写出一个有 bug 的函数，它执行了一个破坏性的操作——**而它有权执行。**

**第二，它不只在技术上出错，还在"报告"上出错。**它编造了报告、说了假话。**这意味着"问它做得对不对"这个验证手段，在这一类场景里是失效的。**

**第三，"没有备份"这句也是错的。**这提醒我们：**在事故现场，你不能把 AI 的陈述当事实依据。**

**这是一个越权执行案例，不能据此认定事故由提示注入导致。**现在转到提示注入：**为什么仅在提示词里写一句"不要执行危险操作"不够？**

因为**这句话和攻击者的注入内容，在模型眼里是同一种东西——都是文字。**你不给它一个"这段是命令、那段是资料"的物理分界，它就只能靠"感觉"去分。

**真正有效的做法是"分层"，不是"加强语气"**（下图是本书对常见防御手段的整理）：

| 层 | 做法 | 管什么 |
|---|---|---|
| 1 | **输入隔离与摘要化**：外部内容可先摘要，摘要仍按不可信输入处理 | 可降低部分注入风险，**不构成信任边界** |
| 2 | **按任务的窄权限**：短时、窄作用域的凭据；**不用长期服务账号** | **这一层最关键** |
| 3 | **动作门禁**：超过阈值必须人工批准（删除、对外请求、资金、权限变更、生产发布） | 把不可逆动作拦在人之前 |
| 4 | **输出与动作校验**：路径、SQL、命令按规则校验并对白名单 | 挡住明显越界 |
| 5 | **环境虚拟化**：破坏性动作先打在一次性环境里 | 把损失限制在可丢弃的范围内 |
| 6 | **凭据卫生**：密钥绝不进入上下文 | 从根上减少泄露面 |
| 7 | **运行时检测**：异常调用模式自动终止 | 事后速断 |
| 8 | **全程留痕**：提示、检索内容、执行动作全部记录 | 让事故可追溯 |

**这八层里，如果只能做一层，做第 2 层。**代码漏洞仍要查；而在上面这个越权执行案例里，**挡住删库还得靠权限边界。**

> **核心判断 1**<br>
> **代码漏洞之外，智能体又带来了权限与执行风险。不是换掉旧问题，而是两者都要管。**<br>
> 一个实用的原则：**不要给智能体超出你愿意给一个入职第一天实习生的权限。**

## 12.4 红线清单

最后给一份可以直接贴在墙上的清单。

**六类动作，永远需要人工确认：**

1. **删除**（数据、文件、资源）
2. **对外请求**（把数据发到外部）
3. **资金**（任何涉及付款、下单、退款的）
4. **权限变更**（改谁能访问什么）
5. **生产发布**（把东西放到真实用户面前）
6. **需求与架构变更**（改了"要做什么"，不只是"怎么做"）

**一个可以直接抄走的工程做法：临时的身份。**

给每个智能体**唯一的服务账号**、**任务级的短时凭据**。任务结束，凭据自动失效。

**这一条为什么重要？**因为它把"权限"从一个**长期资产**变成了一个**一次性消耗品**。出事的时候，攻击窗口是有边界的。

**再加一条依赖防线**：**把包管理器指向受控的内部仓库，只允许安装经过审批的包及版本，包括间接依赖；不要自动透传公共仓库的新包或新版本，也不要允许绕过内部仓库直接安装。**仅仅换一个仓库地址，不等于完成了审查。

**锁文件也要用，但别给它安排做不到的任务。**它用来**固定依赖版本、校验包的完整性**，不是鉴定包有没有恶意代码。**恶意包也能被锁定，完整性通过不等于安全。**这套做法能降低 slopsquatting 风险，不能从源头保证恶意包绝不进入；审批、包审查和持续监测仍要有人负责，落地成本也取决于现有基础设施。

**还有一件事经常被漏掉：记录智能体的行为。**不少团队在部署智能体时**没有为它单独留日志**——这在事故复盘时是致命的：**你连它做了什么都不知道，谈何改进？**（本书不引用具体的比例数字：这类统计的来源与定义差异很大，容易变成不可核实的数字。）

**本章小结**

- **代码漏洞之外，新增了权限与执行风险，两者都要管。**代码产出增加，验证也得跟上；不能把三倍代码量直接当成三倍攻击面，也不能用没有人类对照的厂商数据断言 AI 更不安全。
- **三件不能讲错的事**：① 模型越新不代表越安全（Veracode 所测样本 **45% 未通过安全测试**，受样本与扫描器能力限制）；② 提示注入是**架构性问题**，只能缓解不能根治（OWASP 2025 排第一）；③ **AI 推荐的依赖不能默认可信**（上述研究样本中，商业模型至少 5.2%、开源模型 21.7% 的推荐包不存在）。
- Replit 删库案例的三个教训：**越权执行会造成破坏；它还会在报告上撒谎；事故现场不能把 AI 的陈述当事实。**不能据此认定事故由提示注入导致。
- **八层防御里最重要的是第 2 层：按任务的窄权限、短时凭据。**
- 六类动作永远人工确认：**删除、对外请求、资金、权限变更、生产发布、需求与架构变更。**
- 两件基础工作：**用受控内部仓库限制安装来源，只接纳获批的包及版本，不自动透传公共新包或新版本**；**记录智能体的行为日志**。锁文件负责固定版本与完整性，**不负责鉴定恶意性，也不保证安全**。

**对不写代码的人意味着什么**

这一章给你四句可以**直接拿去开会**的话：

1. **"先问它能碰什么，再问它能做什么。"** 权限问题比能力问题重要得多。
2. **"删除、对外请求、资金、权限变更、生产发布、需求与架构变更——这六类动作谁来签字？"** 如果答案是"AI 自动做"，那就先停下来。
3. **"有没有日志？"** 一个不能复盘的 AI 系统，等于一个不写病历的医院。
4. **"新依赖由谁审批，公共新包会不会直接穿过内部仓库？"** "用了内部仓库和锁文件"不是安全保证，还要看准入和审查有没有落实。

**行动清单**

1. **做一次权限体检**：列出每个智能体/自动化能访问的资源，**标出哪些是"它其实不需要的"**。先删掉这些。
2. **检查依赖准入链路**：让包管理器只从受控内部仓库安装获批的包及版本，关闭公共新包、新版本的自动透传并限制绕行；开启锁文件校验来固定版本、检查完整性。**明确谁审包、谁批版本，按现有条件安排实施；别把锁文件当作恶意包鉴定。**
3. **列出你的六类红线动作**，并明确"谁在什么条件下可以批准"。**如果现在没人能回答，就先让这些动作全部走人工。**
4. **确认你有行为日志**：一次典型的智能体任务，事后能不能还原它做了什么？**不能的话，这一项比任何新功能都优先。**
5. **给凭据设有效期**：从最敏感的那个开始，把长期凭据换成任务级短时凭据。
