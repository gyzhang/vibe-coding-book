# scripts/ —— 生成、校验与交付脚本

> **本目录只放脚本，不放内容。** 书的内容在 `parts/`（手写源）、`images/`、`svg/`。
> 所有脚本都锚定到**本目录的上一级**（= 书目录），因此**在任意目录下都能直接运行**，不受当前工作目录影响。

> ⚠️ **`sensitive.txt` 不在本目录，也不许移进来**（2026-09-20 明确）。
> 它是脱敏词表，必须留在**书目录本层**（`<书目录>/sensitive.txt`）：校验器按 `root/sensitive.txt` 取它，`root` = **命令行传入的书目录**。移进本目录 → 校验器**不报错，只是静默跳过整类脱敏检查**，而全局结论仍显示"通过"。
> 它不属于工具的理由：词表里装的是**这本书的具体脱敏词**（委托方、客户机构名），换一本书词表完全不同——**它是内容，不是配置**。`scripts/` 装的才是"与哪本书无关"的东西。
> **校验器已加防呆**：一旦在任意子目录里发现 `sensitive.txt`，直接判**错误**（退出码 1）并打印移回命令。

## 一、完整交付链（顺序不可调换）

**V3.3 当前阶段**：配图已回填（2026-09-24），发布链已跑通（2026-09-25：138 页 PDF、136 条书签、页码已盖、正反探针全过）；字号在 A4 实际显示尺寸下的复测仍待做。**2026-09-25 目录重构（仿前端 dist 模式，作者裁定）**：全部生成产物收进 `dist/`——自包含（md / 两版 HTML / pdf / images 拷贝），整个文件夹拿走即可部署或阅读；`.gitignore` 只写一行 `dist/`，**此后版本升级不再逐个添加忽略项**。V3.2 产物同步移入 `dist/` 保留。

**多版本校验注意**：`check_manuscript.py` 会扫描 `dist/` 里全部合稿、按「分片零漏拼 / 标题全在位」自动选中当前版本；`probe_text.py` 取 `dist/` 里**最近构建**的一版（探针的用途就是验收刚跑完的这次构建）。若要严格验收某一历史版本，仍建议建临时目录：只放那一版产物，链接 `parts/`、`svg/`、`images/`、根目录 `sensitive.txt` 后对临时目录跑校验。

```bash
cd <书目录>

# 0. 体例闸门：引用块内分行必须显式写 <br>（违规即非零退出，阻断交付）
python3 scripts/fix_hard_breaks.py --check

# 1. 合稿（parts/ → dist/<书名>.md，并把 images/ 拷进 dist/images/）
python3 scripts/build_book.py

# 2. 在线阅读版（dist/<书名>.md + svg/ → dist/<书名>.html，字体外链 /site/fonts/，体积小）
python3 scripts/build_html.py

# 2'. 下载版（同一份 md + svg → dist/<书名>（离线版）.html，字体内嵌 base64，单文件离线可读，约 1.4 MB）
python3 scripts/build_html.py --embed-fonts

# 2.5 配图几何闸门（改过 svg/ 才需要；L5 装饰条不吻合 = 非零退出）
python3 ~/.workbuddy/skills/ppt-generation-expert/scripts/verify_layout.py svg --only L5

# 3. 校验（0 错误才继续；退出码非 0 即停）**门禁在本仓库内，不再依赖技能目录**
python3 scripts/check_manuscript.py .

# 4. A4 PDF（Chrome 排版，约 3–4 分钟；**必须从离线版导出**，字形来源才可控）
python3 scripts/build_pdf.py --html "dist/<书名>（离线版）.html" --out "dist/<书名>.pdf"

# 5. 三层书签 + 元数据（对不上就报错，不猜页码）
python3 scripts/add_pdf_bookmarks.py "dist/<书名>（离线版）.html" "dist/<书名>.pdf"

# 6. 页码（**最后一步，每份 PDF 只跑一次**）
python3 scripts/stamp_page_numbers.py "dist/<书名>.pdf"

# 7. 三形态正反探针（**改过正文用词时必跑**）：验证新文本已在「源分片 / 合稿 md / HTML / PDF」四面就位、旧文本已从四面消失
python3 scripts/probe_text.py . --new "新文本片段" --old "旧文本片段"
```

**改了什么要重跑什么**：

| 改动 | 必须重跑 |
|---|---|
| 只改正文（`parts/`） | 0 → 1 → 2 → 2' → 3 → 4 → 5 → 6 → **7** |
| 只改配图（`svg/`） | **2.5（配图几何闸门）** → 2 → 2' → 4 → 5 → 6（阅读版内联的是矢量源，不重跑就还是旧图） |
| 只改打印样式（`build_html.py` 的 `@media print`） | 2 → 2' → 4 → 5 → 6（**会改分页**，书签与页码必须重算） |
| **换字体 / 改字体栈** | 2' → 4 → 5 → 6，**并复核 PDF 字体清单**（见 §五 第 10 条） |
| 只改打印样式（`build_html.py` 的 `@media print`） | 2 → 4 → 5 → 6（**会改分页**，书签与页码必须重算） |
| 只改协作文档（`00-`/`99-`/`overview.md`） | **不必重跑**（它们不进书） |

> 页码只在链路里盖**一次**。要重盖 → 从第 4 步重跑整条链，不要在成品上再盖一遍（脚本会拒绝，见下）。

**2.5 为什么必须有**（2026-09-20 实测）：`check_manuscript.py` **不查 SVG 几何**，所以"装饰条与宿主圆角不吻合"这类缺陷在书稿里**没有任何闸门会拦**，只能靠人眼。本轮实测书稿 11 张图 **40 处**强调条戳出宿主圆角（29 处左/竖条 + 11 处上/横条），全是 `rx="2"`/`rx="3"` 的 rect。批量修复与判据说明见 `ppt-generation-expert` 的 `round_accent_strips.py`（`--apply` 自动改写）。

**⚠️ 重渲 PNG 的比例不是全库统一的**：内容图是 **2.2×**（1280×720 → 2816×1584），**封面是 1.4×**（1200×1800 → 1680×2520）。**比例必须从既有 PNG 的文件头尺寸反推**（`png_px ÷ svg_viewBox`），按统一比例硬渲会把封面压扁（本轮实测踩到）。另：pymupdf 读 PNG 会按 72dpi 重栅格化，**逐像素比对时不要用它读 PNG**（尺寸会变），用 PIL。

## 二、脚本清单

| 脚本 | 作用 | 输入 → 输出 |
|---|---|---|
| `fix_hard_breaks.py` | **体例闸门**。引用块内要分行必须行尾显式 `<br>`；否则 md 源码看着正常，渲染成 HTML/PDF 时四要素会被压成一段 | `parts/*.md` → 体检（或就地补标记） |
| `build_book.py` | **合稿**。按 `PLAN` 里写死的顺序把分片拼成主稿，并做一次双路复算（合稿结果必须等于各分片顺序拼接，任何漏拼都会当场断言失败） | `parts/*.md`（21 个分片） → `dist/<书名>.md`（并拷 `images/` → `dist/images/`） |
| `build_html.py` | **构建阅读版**。markdown → HTML，把 `svg/*.svg` 逐个内联，重写可读锚点，生成目录与配图索引，套上阅读外壳 | `dist/<书名>.md` + `svg/*.svg` → `dist/` 两版 `<书名>.html` |
| `build_pdf.py` | **构建 A4 PDF**。Chrome headless 排版；页面尺寸/边距由 HTML 的 `@page` 决定，不在这里传 | `<书名>.html` → `<书名>.pdf` |
| `add_pdf_bookmarks.py` | **注入三层书签 + 元数据**。按字号带定位标题、与 HTML 标题清单**逐条比对**，对不上就报错退出 | `<书名>.html` + `.pdf` → 原地安全替换 |
| `stamp_page_numbers.py` | **盖页码**。Helvetica 9pt `#738599` 居中，跳过封面，封面之后重新起号 | `<书名>.pdf` → 原地安全替换 |
| `probe_text.py` | **三形态正反探针**。改过正文用词后，验证新文本在**四个面**（源分片 / 合稿 md / HTML / PDF）各就各位、旧文本已从四面消失。归一化**按形态分开**（只有 HTML 剥标签、还原实体；md 与 PDF 只去 `**` 与空白），并打印归一化前后的长度差 | 全形态产物 → 探针报告（退出码非 0 = 未落地） |
| `check_manuscript.py` | **书稿门禁（本书仓库内副本）**。原 20 类检查（脱敏、图片正反、SVG/PNG 配对、中英间距、体例积木、图号连续、合稿完整、H1 骨架、条目数声明、跨章引用、附录 A 编号与指向、直译黑名单、加粗配对、汉字间空格）＋ **V3.3 新增三道闸门**（见下） | `parts/*.md` + `svg/` + 两个登记表 → 错误/提醒/通过三档（退出码 1 = 有错误） |

### V3.3 新增的三道闸门（把 `96` §5 第二轮复核固化成代码）

| 闸门 | 拦什么 | 对应的真实失效 | 级别 |
|---|---|---|---|
| `check_quote_forms` | 正文与图内混进弯引号 `“ ” ‘ ’`（全书体例是 ASCII 直引号） | 第一轮批量修订留了 8 处，原有 20 类检查全部放行 | **错误** |
| `check_probes` | 已改口的断言被改回去、该落地的关键句没落地 | 第一轮的「14 正向 + 8 反向」短语没进任何文件，第二轮无法复跑 | **错误** |
| `check_figure_numbers` | 图内带单位的数值在正文/附录里查不到出处 | `fig-3-2` 的 $0.243/$0.114/128,000 token、`fig-4-4` 的 250 多个成员机构等，此前无人发现 | 提醒（挂账） |

两个登记表与书稿同仓，**改判据前先改表**：

- **`scripts/probes.txt`** —— 语法 `+ 短语 [次数]`（必须出现）/ `- 短语`（正文必须 0 命中）/ `! 短语`（图内必须 0 命中）/ `#` 注释。**只追加不删**：旧条目是最便宜的"别把改口改回去"护栏。图侧尚未闭环的残留先由 `95` 的 F 条目挂账，回填后再逐条转成 `!`。
- **`scripts/figure-numbers-ok.txt`** —— 一行一条 `图名<TAB>数值<TAB>理由`，**没理由不许登记**。只用于"正文确实有同一个量、只是写法不同"（附录写「官网 12」、图内写「12 次」）；**不许**用来掩盖"图里有个正文查不到的数"——那正是这道闸门要抓的东西。

判据为什么是「数字主干 ＋ 同类单位邻近共现」：只比数字串，会把图里的 `731 次` 和附录的 `**731**` 判成对不上；只比"数字在不在正文"，又会让已经改口的 `39 个百分点` 蒙混过关。四位以上主干近乎唯一，出现即算对上。

## 三、纪律（违反会静默出错）

1. **`parts/` 是唯一手写源。** `<书名>.md` 是合稿产物，**任何手改都会在下次合稿时丢失**。
2. **`images/` 与 `svg/` 必须同名成对**。PNG 给 md 用，SVG 给阅读版/PDF 内联；**改数据时改 SVG 重渲染，不要重画**。
3. **改了 SVG 就必须重跑 `build_html.py`**，否则阅读版与 PDF 里还是旧图。
4. **脚本不要用相对路径取文件。** 一律 `os.path.join(ROOT, ...)`，其中 `ROOT` 是「本脚本上一级」。这条曾经踩过：`build_book.py` 早期用裸相对路径，**只有在书目录下运行才不崩**。
5. **`sensitive.txt` 留在书目录本层，不进 `scripts/`。** 详见开头的警示。
6. **页码脚本不幂等**：连跑两次会在**同一坐标叠两份文字**，渲染出来只是"略粗"，肉眼看不出来，但选中复制会得到 `63 63`。已加防呆——盖之前先扫页脚带，发现已盖即报错退出（`--force` 才允许强盖）。

## 五、十个已固化的坑（每条都对应脚本里的一段注释或断言）

| 坑 | 症状 | 处置 |
|---|---|---|
| **字号带照抄** | 换本书（或改了打印 CSS）后"PDF 抓到候选"条数 ≠ 标题数 → 拒绝写书签 | `add_pdf_bookmarks.py <html> <pdf> --probe` 重校 |
| **Chrome 子进程继承 stdout** | PDF 早就写好了（文件在长），命令却一直不返回（实测挂了 **3 分 45 秒**） | 输出落文件而非管道 + 独立进程组 + 收尾 `killpg` |
| **pymupdf 不能 save 回原件** | 原地覆盖报错；增量保存会把新旧内容叠起来 | 一律「临时文件 + 原子替换」 |
| **页码叠加** | 见纪律 6 | 防呆 + 链路只跑一次 |
| **网页操作提示被印进 PDF** | 第 1 页出现"点击任意配图可放大（Esc 关闭）…"这类**网页专属说明** | 打印样式里 `.hint{display:none}`（`.draftbar` 保留——它是版本与口径说明，属于书的内容） |
| **封面页数靠假定** | 封面 SVG 的副标题字号会落进标题带，制造假标题 | 实测「第 2 页第一行是不是第一个标题」，不假定 1 页 |
| **`build_pdf` 静默交付陈旧 PDF**（2026-09-20 实测） | "产物稳定"判定只看**磁盘上已有文件**体积连续两次不变，**不校验是不是本次写的**。Chrome 对 135 页要跑约 30 秒 > 3 秒判定窗 → 连续两次 build_pdf 都返回**上一轮的已盖章 PDF**，靠 `stamp_page_numbers` 的防呆才暴露 | 启动 Chrome **之前先 `unlink` 旧产物**——判定只能命中本次新写的文件 |
| **探针把"自己取错了文件"报成"改稿没落地"**（2026-09-22 实测） | `probe_text.py` 首版用"排除 `00-`/`99-` 前缀"去 glob 根目录 `*.md`，**第一个命中的是 `README.md`** → 四个正向探针全部报"未落地"，看起来像改稿没落地。**判据换成"与 HTML 同名"**（三形态同名是目录契约） | 报"未落地"之前，先证明**不是自己取错了对象**；取文件不要用前缀排除法 |
| **归一化会删掉证据，把"已落地"报成"没落地"**（2026-09-21 实测） | PDF 正文里**合法**出现 `<`（表格格「2 天人工 + `<50 元 token`」），与后面的 `>` 配成"假标签"，一句剥标签正则**一口气吞掉 61,707 字符** → 四条正向探针全报 0 | 归一化**按形态分开**（HTML 才剥标签）；**必须打印归一化前后的长度差**，差了几万字符就是证据被删了 |
